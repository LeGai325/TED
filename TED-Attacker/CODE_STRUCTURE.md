# CODE_STRUCTURE

In the interest of reproducibility and transparency, we provide the complete implementation of our proposed system. The source code is organized into modular components that handle measurement, path planning, and attack execution. The following section describes the specific functionality of each file within the repository.

### **tunnel_sender.c**

This module implements the initial measurement phase by calculating the latency between the Prober and each individual Node. It constructs IPv6-in-IPv6 encapsulated tunnel packets, and pads them with extension headers.. By sending asynchronous probes, it establishes a baseline for Prober-to-Node RTTs.

### **tunnel_mesh_measure.c**

It constructs nested tunnel packets designed to traverse from a primary Node A to a secondary Node B before returning to the prober. This "loopback" mechanism allows the system to isolate the intermediate link delay between any two nodes in the mesh.

### **tunnel_mtu_probe.py**

Determining the Path MTU is critical for avoiding packet fragmentation during multi-hop encapsulation. This module performs binary search and incremental probing across all tunnel paths. The results are fed into the "MTU-Aware Nesting" logic of the planner to ensure that deep nesting remains within the physical limits of the network links.

### **tunnel_link_delay.py**

This data processing utility parses the raw outputs generated by the measurement modules. By applying a subtractive algorithm—removing the Prober-to-Node delays from the composite path latencies—it extracts the precise link delays between tunnel nodes, outputting a structured `delay_results.csv` for the planning stage.

### **tunnel_victim_tracer.c**

This file implements the "ICMP TTL Expiration Scan" to measure the latency between the exit nodes and the target (Victim). By injecting packets with a Hop Limit (TTL) of 1 within the final tunnel layer, it elicits ICMP Time Exceeded messages from the victim’s gateway, thereby calculating the final-hop latency.

### **one_hop_injector.c**

As a diagnostic tool, this lightweight injector sends single-hop tunnel packets. It is primarily used for baseline verification, connectivity testing, and validating the amplification factor of a single encapsulation layer without the complexity of nested scheduling.

### **multi_hop_scheduler.c**

Acting as the core Attack sender, this module executes the synchronized pulse. It reads a high-precision `attack_schedule.csv` and dynamically constructs packets with variable nesting depths. The scheduler strictly adheres to the calculated `send_time_s` timestamps, using high-resolution timers to ensure that packets from disparate paths converge at the victim simultaneously.
